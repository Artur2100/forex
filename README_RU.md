# Forex Intelligence Agent v0.4 — бесплатный облачный MVP

## Назначение
Бесплатный периодический мониторинг через GitHub Actions с уведомлениями в Telegram. Компьютер пользователя может быть выключен. Автоматической торговли и отправки ордеров нет.

**Это аналитический исследовательский инструмент, не финансовая рекомендация и не гарантия прибыльности.** Включены только технические предупреждения. Финальные торговые сигналы намеренно заблокированы до проверки источников котировок, экономического календаря, бэктеста и форвард-теста.

## Что реализовано
- EUR/USD, GBP/USD, USD/JPY, AUD/USD, USD/CAD, USD/CHF и GC=F (фьючерс на золото как отдельный proxy, не spot XAU/USD).
- D1/H1 анализ по закрытым свечам: EMA20/EMA50, RSI14, ATR14, ADX14 и наклон быстрой EMA.
- Проверка полноты индикаторов и давности последней закрытой свечи.
- Консервативные фильтры: совпадение D1/H1, направление наклона EMA, диапазон RSI и минимальный ADX.
- Иллюстративные ATR-уровни с модельным R:R 1:3; это не торговые уровни брокера.
- RSS-заголовки центральных банков (ФРС, ЕЦБ, Банк Канады, Резервный банк Австралии).
- Telegram-уведомления и сохранение истории отправленных предупреждений через GitHub Actions cache.
- Автоматические unit-тесты перед каждым сканированием.
- Запуск по расписанию раз в 15 минут и вручную через Actions.

## Критические ограничения
1. Yahoo Finance — сторонний источник, не котировки Альфа-Форекс. Возможны задержки, пропуски, изменения API и расхождения с исполняемой ценой.
2. Для золота используется GC=F — фьючерс COMEX, а не спотовый XAU/USD. Не переносить его цены напрямую на брокерский график.
3. Для валютных пар Yahoo Finance также не гарантирует поток реального времени или совпадение с брокером.
4. GitHub Actions — периодические задания, не постоянный сервер 24/7. Cron может запускаться с задержкой и иногда пропускаться.
5. RSS центральных банков — неполный поток пресс-релизов, не календарь макроэкономических событий.
6. Корреляционный модуль не валидирован и не используется как фильтр.
7. ATR Entry/SL/TP — исключительно математические ориентиры; не учитывают спред, комиссию, своп, проскальзывание, гэпы, ликвидность и спецификации инструмента у брокера.
8. RSI/ADX/EMA — фильтры, а не доказательство преимущества стратегии. Их пороги ещё требуют статистической проверки.
9. Кэш GitHub Actions помогает сохранять дедупликацию предупреждений, но не является полноценной транзакционной базой данных.
10. Ни один результат не следует использовать для входа без самостоятельной проверки графика и риска.

## Секреты GitHub
В Settings → Secrets and variables → Actions должны быть заданы:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

Токен нельзя публиковать, коммитить в код или отправлять в переписку. При утечке его нужно отозвать через @BotFather и обновить секрет.

## Структура
- `fia/config.py` — инструменты, периоды, индикаторы, RSS и защитные переключатели.
- `fia/market_agent.py` — загрузка рыночных данных.
- `fia/technical_agent.py` — индикаторы и проверка свечей.
- `fia/decision_agent.py` — фильтры допуска предупреждений.
- `fia/risk_agent.py` — только иллюстративные уровни.
- `fia/news_agent.py` и `fia/macro_agent.py` — ограниченный новостной контекст.
- `fia/main.py` — оркестрация и Telegram.
- `.github/workflows/scan.yml` — расписание, тесты и запуск.
- `tests/` — unit-тесты.

## План развития без платных сервисов
1. Проверить стабильность источников и сравнить цены с брокерским графиком.
2. Добавить бесплатный календарь только после проверки лицензии, полноты, часового пояса и времени публикаций.
3. Реализовать исторический тест с реалистичными спредом, комиссией, свопом и проскальзыванием.
4. Проверить walk-forward и out-of-sample периоды, не подгоняя параметры под прошлое.
5. Вести журнал предупреждений и измерять частоту, MAE/MFE, expectancy и просадку.
6. Только после достаточного форвард-теста отдельно рассматривать включение полноценных сигналов.

Никаких обещаний win rate или доходности. Система должна уметь говорить «нет сделки», если данные или условия недостаточны.


## Журнал предупреждений и статистика v0.5
Файл `journal.csv` хранит каждое уникальное техническое предупреждение. Это журнал гипотетических сетапов, а не реальных исполненных сделок.

- Вход условно считается по цене закрытия сигнальной H1-свечи.
- TP/SL проверяются по последующим H1 high/low.
- Если одна свеча задела и TP, и SL, результат помечается `AMBIGUOUS_SAME_CANDLE`, а не выбирается удобный исход.
- Через 7 дней без касания уровней запись получает статус `EXPIRED_7D`.
- Win rate считается только по однозначным TP/SL; комиссии, спред, своп и проскальзывание пока не моделируются.
- GitHub Actions сохраняет `journal.csv` и `fia_state.json` коммитом в репозиторий после успешного сканирования. Репозиторию нужны workflow permissions с правом contents: write.
- Результаты не являются фактическим P&L пользователя. Реальные сделки нужно вести отдельно с фактическими ценами входа/выхода и издержками.
